# 重构结论与产品验收

本报告综合了三条相互独立的检查线：代码与数据模型根因审计、完整反馈历史复盘、真实产品与视觉交互验收。结论不以“自动化测试通过”代替产品合格；自动门禁、生产数据统计、受限网络测量和人工截图分别提供不同层面的证据。

## 用户真正纠结的核心问题

用户要的不是给旧页面换主题，而是一个值得相信、可浏览、可解释、能交付的竞赛资料库：

1. “数据不全”不仅是记录数量少，还包括状态混入、关系残留、角色乱猜、机构误合并、未知值被吞掉以及历史奖项来源不足。
2. 页面必须明确区分官方事实、派生规则、当前公开档案和历史事实，不能用看似完整的数字掩盖证据缺失。
3. 产品需要接近高级资料库 / OIerDB 的信息密度和秩序感，而不是渐变、玻璃、过度圆角和模板化 AI 卡片。
4. 交付必须能在生产数据、真实浏览器、移动端和受限网络中复验，而不是只在 fixture 或单元测试里成立。

## 已真正解决的问题

### 数据真相层

- 默认产品集合从 raw 审计集合中明确投影：5,518 支 raw 队伍中仅 5,280 支 accepted 队伍默认可见（2026-09-06 刷新）；191 支 withdrawn、28 支 disqualified 和 19 条 demo/test 记录保留但隔离。规则见 `tools/igem_scraper/igem_scraper/publication.py`，生产门禁见 `tools/igem_scraper/igem_scraper/validate.py`。
- 一般 student 不再被猜成本科生；只派生中性 `Student`，`Undergrad` / `Graduate` 必须有公开 title 证据。当前 1,335 条 Undergrad 中无 title 证据的记录为 0。
- 名单、详情和逐队奖项在成功请求后做事务性精确 replace-set；上游删除的关系会被删除，请求失败则保留最后一次成功集合。回归测试位于 `tools/igem_scraper/tests/test_refresh_semantics.py`。
- live 年份不会被旧 resume 状态永久跳过；schema v3 记录端点模板、规则版本、逐阶段成功时间和 freshness。
- 生产快照已重新导出并通过引用、状态、覆盖率与 freshness 校验。2026-09-06 刷新后 `public/data/igem.json` 为 43,203,088 bytes，SHA-256 为 `BAA138FB837D350BE9DA92C2DE914E0D9C9AFE570B2A7CB7D615F2AAF8B861D3`。

### 前端语义层

- 默认目录、统计、搜索和年度页只消费默认可见集合；显式状态筛选才读取 raw 队伍，撤回记录会显示状态 badge 和详情警示。
- 公开机构目录只由默认可见队伍的官方机构字段建立。成员当前 affiliation 不再伪造队伍—机构边；机构名称不再删词、乱序或跨国家激进合并。Miami / Newcastle 误合并已成为回归测试。
- 空组别、地区和国家进入显式 unknown 分类，年度分布保持数量守恒；人物时间线不再把当前 title / affiliation 冒充历年快照。
- 首页不再下载 42.6 MB 完整快照：冷启动读取核心目录，队伍详情读取 64 个桶之一，成员详情读取 256 个桶之一，完整人员索引只在人员目录或全站检索时加载。守恒和包体由 `tools/validate_web_data.mjs` 强制验证。

### 产品与 UI

- 已重做为克制的 Swiss / editorial archive 风格：米白纸面、墨绿色、直角区块、细网格、衬线标题和等宽元数据，无渐变、玻璃拟态或大面积圆角卡片。
- 原生 `dialog` 提供模态语义、焦点闭环、Esc 关闭和回焦；支持 Ctrl/⌘K、跳到主要内容、可见焦点和 reduced motion。
- 方法页展示默认 / raw 双口径、逐年请求完成情况、来源边界、隐私纠错和横向表格提示；队伍详情展示记录级来源端点与最近成功抓取时间。
- 1440、1024、768 和 390 px 浏览器检查无页面级横向溢出；正文不低于 14 px、元信息不低于 12 px。证据见 `output/ui-premium/browser-evidence.json` 和 `output/final-product/` 截图。

## 只解决了表面的问题

- 对老年份奖项，产品现在会诚实显示“端点已请求但无结果”，解决了误导性表达，却没有补回官方 API 本身缺失的历史奖项。
- 隐私与纠错已有入口和说明，但目前仍落到 GitHub Issue，没有独立工单、身份核验、处理时限和撤回审计链。
- 机构策略通过保守不合并消除了高风险误合并，但别名仍可能拆成多个名称记录；这不是权威机构主数据系统。
- 双区域原子发布、健康检查和回滚工作流已经写入仓库并做静态审查，但尚未在本次本地任务中实际连接生产服务器执行。
- SPA 内部有可理解的 404 页面；静态托管回退仍会对未知路径返回 HTTP 200，搜索引擎级的真实 404 尚未解决。

## 尚未解决的结构性问题

1. 采集层尚未保存每次原始 API payload、响应 hash、HTTP 元数据和正式 scrape-run ID，无法做到字段级历史重放。
2. 2004、2005 的当前奖项端点为 0 条，2007 仅 1 条；需要官方 wiki、历史结果页等多个权威来源交叉补录。
3. 人物 title 和 affiliation 仍只是抓取时公开档案，没有逐年历史快照；产品已停止伪装，但数据能力本身尚未补齐。
4. 完整人员索引 gzip 约 3.80 MB。在 512 KiB/s、150 ms 延迟、4 倍 CPU 降速下，人员目录冷启动约 14.0 秒（2026-09-06 复测）；它已不再拖慢全站，但该重载页仍需进一步分页索引或服务端搜索。
5. 数据纠错、撤回和再发布没有独立治理后台、SLA、审计日志和通知闭环。

## 当前实现过去为什么反复达不到目标

- 把“字段有值”当成“事实有证据”，用默认值和启发式推断制造完整感。
- 测试主要验证 fixture 能渲染，没有用生产快照检查状态分布、分类守恒和实体关系。
- 采集采用追加 / upsert 思维，没有建模“官方删除或撤回”的同步语义。
- 人物自由文本机构被提升成正式机构实体，数据模型把当前档案与历史参赛关系混在一起。
- 完整 JSON 被所有路由同步下载，数据越“完整”，产品越不可用。
- 视觉修补先于信息架构和数据口径，页面好看与数据可信彼此脱节。
- 部署直接从工作区复制，没有确保线上产物就是已通过门禁的同一份 artifact。

## 分阶段改进方案

### 阶段 0：本次交付（已完成）

修复状态、角色、机构、replace-set 与 live freshness；重建前端信息架构、视觉系统和按需数据包；补齐自动门禁、浏览器脚本、文档和发布 artifact 流程。

### 阶段 1：可重放数据管线

为每次采集增加 run ID、原始响应压缩存档、响应 hash、HTTP 状态与源 URL；建立从 raw response 到规范化行的可追溯映射。完成标准是任意一条展示记录都能定位并重放其来源响应。

### 阶段 2：历史奖项补全

建立来源优先级和冲突规则，优先处理 2004–2007，再扩展所有历史年度；每条补录保存来源、抓取时间、匹配置信度和人工复核状态。未达到双来源或官方单一权威来源时不得标记为完整。

### 阶段 3：身份、机构与纠错治理

维护受审计的机构 alias 表；引入纠错 / 撤回工单、最小身份核验、处理 SLA 和再发布审计日志；只在证据足够时合并实体。

### 阶段 4：规模与运营

把人员检索改为预建前缀索引、服务端查询或更小的搜索分片；在两区域执行发布、故障注入和回滚演练；增加真实用户监控但不采集敏感个人搜索内容。
