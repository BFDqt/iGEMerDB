## 完整性语义

- 每年队伍清单都与官方接口重新对账；撤回、取消资格和 demo/test 行保留在 raw 发布快照供审计，但默认产品视图隔离这些记录。
- 每支当前公开队伍都完成了详情、名单和逐队奖项端点请求。端点返回空数组会记录为“已完成但无公开记录”。
- 公开名单只代表 iGEM API 在快照时点公开的成员，不代表未公开、未接受或已撤回的参与者。
- roster、队伍奖项和详情在成功返回后使用精确 replace-set；官方删除的关系不会继续残留。失败请求保留上一份成功集合并记录错误。
- 2026 为进行中赛季；默认同步会强制刷新 live 年份，freshness 门禁要求不超过 48 小时。
- 发布门禁检查逐队抓取标记、抓取错误、重复主键、名单与奖项孤儿关系、逐年覆盖计数和角色映射版本。
- schema v3 在 `meta.provenance` 中记录官方端点模板、角色规则版本与逐阶段时间字段。每支队伍保存详情、名单和奖项最近成功检索时间。
- 浏览器启动使用 `public/data/web/core.json`，而不是完整快照；核心包 gzip 必须不超过 512,000 bytes。队伍和成员详情通过校验后的哈希分片按需加载。完整 `igem.json` 继续作为 raw 审计资产。

## 已知来源缺口

- 2004、2005 的当前官方奖项端点返回 0 条，2007 仅返回 1 条；这不等于这些年份历史上没有奖项。
- 旧年份奖项仍需要官方 wiki、历史结果页等第二来源对账，未补齐前不得将单一 API 投影称为完整历史奖项档案。
- 成员机构和 title 是抓取时公开档案，不是参赛年份的历史状态；产品时间线不会将其作为年度事实展示。
- 可重放管线会把每份原始名单响应（含成员姓名、用户名、院校）gzip 存档在 `raw_response` 表中，用于逐字节溯源；成员从官方名单移除后，产品视图会随 replace-set 裁剪，但历史归档体目前没有自动清除路径。纠错与撤回请通过 GitHub Issue（标签 data-correction）提交，由维护者手工核实并处理——含归档体的定向清除；目前暂无自动化流程与处理时限（SLA）。
